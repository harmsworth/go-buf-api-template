## P0：上线前必修

### 1. 零测试（最大短板）—— 🟡 部分完成（8 个测试文件；Handler 层 httptest 待补）
- **现状**：2456 行手写代码，**0 个 `_test.go`**；`docs/EXAMPLES.md` 写了测试范式但无落地代码；Makefile/CI 也无 `go test` 步骤。
- **风险**：AIP filter 翻译、PATCH 三态、枚举解析这类纯逻辑没有回归网，改一行就可能静默出错。
- **改法**（按性价比排序）：
  1. `internal/platform/aipgorm`：纯函数单测，`translate`/`constValue`/`enumNumber` 直接断言 SQL 与 args（无需 DB，**半天，收益最大**）。
  2. `internal/todo/model.go`：`applyUpdate` 的两种语义（mask 模式 / 三态模式）表驱动测试（**半天**）。
  3. `Service` 层：用 `sqlmock`（或 testcontainers 起真 MySQL）覆盖 CRUD + 软删除 + ErrNotFound（**1 天**）。
  4. `Handler` 层：`httptest` + `protojson` 构造请求，覆盖 400 校验失败与 404（**半天**）。
  5. CI 加 `go test ./... -race -cover`，Makefile 加 `test` 目标并纳入 `check`。
- **工作量**：约 2–3 人日。

### 2. 明文密钥 + 配置无环境变量覆盖
- **现状**：`configs/config.yaml` 里 `jwt.secret: "1221233232"`、DSN 含 `root:123456`；`platform/config.Load` 只读文件，**无 env 源、无 `${ENV:default}` 占位**。
- **风险**：密钥必然进 git；换环境要改文件重新发布。
- **改法**：
  1. `conf.proto` 只保留非敏感项，secret/DSN 改为启动时从环境变量注入（`DATABASE_DSN`、`JWT_SECRET`），缺失即 fail-fast。
  2. 或在 `config.Load` 里加一层 env overlay：先读 YAML → JSON → 遍历 `${ENV:default}` 占位替换（可直接抄 Kratos `config/env` 的做法）。
  3. `configs/config.yaml` 只留占位值，补 `.env.example`，并在 README 明令禁止真实密钥入库。
- **工作量**：半天。

### 3. 启动即执行迁移
- **现状**：`cmd/server/main.go` 的 `provideDB` 里直接 `database.Migrate(db, log)`，且 `EnsureDatabase` 会自动 `CREATE DATABASE`。
- **风险**：多副本并发发布时多个进程同时跑迁移；迁移失败直接拖垮服务启动；生产库被应用账号 DDL 权限放大。
- **改法**：`conf.Database` 加 `auto_migrate` 开关（本地默认 true，生产 false），生产由独立 migration job / initContainer 执行；`MigrateWith` 已可复用，改造成本很低。
- **工作量**：2 小时。

### 4. 错误映射分裂 + 语义丢失 —— ✅ 已完成（errorsx）
- **现状**：HTTP 侧 `writeStatusError`（todo/user handler 各一份）与 gRPC 侧 `gRPCError`（各一份）是**两套映射表**；`user.ErrDuplicateUser`（唯一键冲突）在 HTTP 侧落进 default → 500，正确应是 409；Service 直接把 gorm 原始 error 往上抛，客户端只看到 500，日志与响应无关联 ID。
- **风险**：新增一个领域错误要改 4 处；冲突类错误被当成服务端故障，客户端无法区分重试与否。
- **改法**：抽一份集中映射（如 `internal/platform/errorsx`：`MapStatus(err) (httpCode, grpcCode)`），HTTP 与 gRPC 共用；补 409/429 分支；响应体统一为 `{code, message, details, request_id}`（对齐 Google API 错误规范，也能与 gateway 侧输出一致）。
- **工作量**：1 天。

### 5. Gin 裸跑：缺 CORS / 安全头 / 限流 / Body 限制
- **现状**：`gin.New()` 只挂了 `gin.Recovery()` 与访问日志。
- **风险**：公网暴露即裸奔；大 body 无上限；无慢请求/超时治理。
- **改法**：加 CORS（显式来源，禁用通配）、安全头、`c.Request.Body = http.MaxBytesReader(...)`、按 IP+路由限流（`golang.org/x/time/rate`），server 侧设 Read/Write/Idle 超时。
- **工作量**：半天。

### 6. 认证是留桩 + 无登录风控
- **现状**：`Service.Login` 返回 `stub-access-token`；`UserStatus.USER_STATUS_LOCKED` 已定义但**从未使用**；登录失败无限次；`last_login_at/last_login_ip` 已记录却没用于风控。
- **风险**：直接上线等于无鉴权。
- **改法**：接入 JWT（短时效 access + 服务端 refresh，禁止 localStorage 存储）、登录失败计数与锁定（复用已定义的 LOCKED 状态）、密码策略走 `buf.validate` 已声明的规则。
- **工作量**：1–2 天（取决于是否引入现成认证库）。

## P1：架构与可维护性

### 7. 缺仓储接口（依赖倒置缺失）—— ✅ 已完成
- **现状**：`Service` 直接持有 `*gorm.DB`（`todo/service.go`、`user/service.go` 皆然）。
- **风险**：业务逻辑与 GORM 强耦合，单测只能 mock 驱动；将来加缓存/换存储要动业务代码；不符合对比报告里强调的分层纪律。
- **改法**：每个业务包声明 `type Repo interface`，`Service` 依赖接口，实现放在 `internal/<domain>/repo` 或 `internal/platform`；wire 里替换绑定即可。
- **工作量**：1 天（两域）。

### 8. 无 request_id / trace_id
- **现状**：slog 日志里没有请求维度字段，Gin 访问日志只有 method/path/status/latency/client_ip；无 OTel 依赖。
- **风险**：线上排障无法把一次请求的多条日志串起来。
- **改法**：加中间件生成 `request_id`（入参取 `X-Request-ID`，否则生成），写入 context 与响应头，slog 统一携带；接入 OTel 后用 `TraceAttrs` 把 trace_id/span_id 注入 logger（可直接抄 kratos-layout 的做法）。
- **工作量**：半天（基础）/ 1–2 天（含 OTel）。

### 9. 健康检查不完整
- **现状**：只有 `/healthz` 恒定返回 `{"status":"ok"}`，不探 DB。
- **风险**：DB 已断但 k8s 仍判定就绪，流量继续打进来。
- **改法**：拆 `/healthz`（进程存活）与 `/readyz`（`sqlDB.PingContext`），并加 `/version`、`/metrics`（若接 OTel/Prometheus）。
- **工作量**：2 小时。

### 10. 双 REST 入口语义重复 —— 🟡 部分完成（入参语义已统一；入口收敛待决策）
- **现状**：Gin `:8080/api/v1/todos` + gateway `:8081/v1/todos` 同时开放，两套错误格式（Gin 自造 `{code,message}` vs gateway 的 gRPC 错误 JSON）。
- **风险**：前端不知道调哪个；两套契约文档；长期维护成本翻倍。
- **改法**：明确主入口（建议保留 gateway 作为对外 REST，Gin 仅在需要自定义中间件/非 proto 路由时保留），并在 README 标注；或把 Gin 侧的响应格式对齐 gateway。
- **工作量**：决策 1 小时，改造半天。

### 11. 分页是 offset 游标
- **现状**：`pageToken` 里存的是 offset，深翻页越往后越慢；`page_size` 上限 100 但 offset 无上限。
- **改法**：改 keyset 游标（token 带最后一行的排序键值），或至少限制最大 offset；`List` 里"多取一条判 next"的写法可保留。
- **工作量**：半天–1 天。

### 12. 缺 Dockerfile / 编排 / LICENSE / 提交规范
- **现状**：对比 kratos-layout 有 Dockerfile，本仓库没有；也缺 LICENSE、CHANGELOG、CODEOWNERS（`docs/README.md` 自己提到未配置）。
- **改法**：补多阶段 Dockerfile（非 root 运行 + HEALTHCHECK）、`docker-compose.yml`（MySQL + 服务）、LICENSE、CODEOWNERS（`api/`、`gen/`、`db/migrations/` 强制评审）、CONTRIBUTING 里写 Conventional Commits。
- **工作量**：半天。

### 13. 生成物未标记为 generated —— ✅ 已完成（.gitattributes）
- **现状**：`gen/**` 与 `internal/conf/conf.pb.go` 提交入库，但无 `.gitattributes`，PR diff 全量展开。
- **改法**：抄 kratos-layout 的 `.gitattributes`：`*.pb.go`、`*_grpc.pb.go`、`*.pb.gw.go`、`wire_gen.go`、`gen/**` 标 `linguist-generated=true`；另加 `*.proto text eol=lf` 保证跨平台一致。
- **工作量**：15 分钟。

## P2：细节打磨

### 14. 排序默认键不稳定
- **现状**：`ApplyOrderBy` 的 fallback 是 `id ASC`，而 ID 是 **UUIDv4（无序）**，同一 `created_at` 下顺序不稳定。
- **改法**：默认改为 `created_at DESC, id ASC`；或直接换 UUIDv7（kratos-layout 用 v7，天然时间有序，offset 分页也更稳）。
- **工作量**：1 小时。

### 15. Update 先读后写，无并发保护
- **现状**：`Service.Update` 先 `First` 再 `Save`，并发写会丢更新。
- **改法**：加 `version` 列做乐观锁（`WHERE id=? AND version=?`），或把读改写进事务 + `FOR UPDATE`。
- **工作量**：半天。

### 16. 兼容字段未标记废弃
- **现状**：`ListTodosRequest.status`（注释自称"旧字段，保留兼容"）与 `filter` 并存，且是 AND 叠加。
- **改法**：proto 里加 `deprecated = true`，文档写明移除版本；`List` 中两者叠加的语义写进注释与 README。
- **工作量**：30 分钟。

### 17. aipgorm 的时间与函数覆盖
- **现状**：timestamp 常量以字符串形式交给 MySQL 解析（依赖服务端时区配置）；不支持 `IN`、不支持 `duration`；不支持运算符的错误提示未列出白名单。
- **改法**：时间改为显式 `time.Time` 参数传递；错误信息里回显 Schema 允许字段与操作符。
- **工作量**：半天。

### 18. 日志组件副作用 —— ✅ 已完成（New 返回 cleanup；另加 Nop / Bootstrap）
- **现状**：`logger.New` 内部 `slog.SetDefault`（全局副作用）且打开的文件句柄永不关闭。
- **改法**：返回 cleanup 函数，纳入优雅退出；或改由调用方决定是否 SetDefault。
- **工作量**：30 分钟。

### 19. 路由注册需改 main.go —— ✅ 已完成（httpx.Registrar + providers 聚合）
- **现状**：`todo.RegisterRoutes` / `user.RegisterRoutes` 在 `main.go` 里逐个手调，新增域要动入口文件。
- **改法**：定义 `type Router interface{ Register(*gin.Engine) }`，wire 聚合 `[]Router`，main 里循环注册。
- **工作量**：1 小时。

### 20. Makefile / CI 小项 —— 🟡 部分完成（`test` / `wire-drift` 已加；缺 golangci-lint 与 `-race`）
- `check` 不含 `go test`（补测试后纳入）；`proto-format` 依赖 `diff`，Windows cmd 下不可用（已注释说明），可加 `buf format --diff` 的替代分支或明确 CI-only。
- CI 的 `go build`/`go vet` 已覆盖，但可加 `golangci-lint` 与 `-race` 测试。
- **工作量**：1 小时。
